# CLAUDE.md

Generic monorepo boilerplate. Clean Architecture + DDD. No business features. This file holds only what is true across the whole monorepo; everything that names an app or a package lives in that app's or package's own `CLAUDE.md`, auto-loaded by Claude Code the moment you read or edit a file under its path.

**What ships** (inventory, not rules): [`docs/OVERVIEW.md`](docs/OVERVIEW.md) is the plain-language guided tour · [`docs/FEATURES.md`](docs/FEATURES.md) is the file-level inventory · [`docs/PUBLIC-API.md`](docs/PUBLIC-API.md) is the third-party reference for `/api/v1` · [`ROADMAP.md`](ROADMAP.md) is what's next.

## Philosophy

Lean Startup, **Build → Measure → Learn**. The stack ships SaaS plumbing (auth, billing, multi-tenant, email, storage) and isolates the domain so pivots don't trash the foundation. "Done > perfect" applies to features; the rules in the guides are non-negotiable, they are what *makes* shipping fast sustainable.

Library API, config or state of the art unclear → **check the docs first**; outdated patterns are a frequent failure mode. Primary source: Context7 MCP. Fallback: web search or fetch.

## Cross-cutting rules (always apply)

1. **Adding a rule: omnipotent or it doesn't belong.** A rule states a *principle* tied to an architectural property and survives swapping any library, version or path it references. Phrase it library-agnostic; only name a tool when it *is* the property (a schema validator = "validate at the boundary"). Always include the **why**. Promote on the 2nd occurrence. Rewrite or delete a rule the moment its property changes. A rule that would not change what an agent does, or that repeats another guide, is deleted, not kept "for completeness".
2. **Reusability-first: promote, don't duplicate.** 2nd occurrence is the trigger. Once promoted, the call site has zero cosmetics.
3. **Zero warnings, zero errors before push.** Husky, lint-staged and commitlint green locally; `.husky/pre-push` runs `pnpm ci:check` (Biome), `turbo run build type-check test`, `check:duplication` (jscpd) and `check:unused` (knip); CI (`.github/workflows/ci.yml`) additionally runs the checks that need real infrastructure (a real database, a browser accessibility audit), listed in the app guides. No `--no-verify`. Intentional warning → `/* biome-ignore <rule>: <why> */`. Contract: the whole pre-push chain green. **Accessibility is a gate, not a polish pass**: CI fails a PR on any `serious`/`critical` WCAG 2.1 AA violation, on a page with two `<main>` or no `<h1>`, or on a broken tab order or focus trap. **Why the assertions and not just an audit engine**: a rule engine cannot see that a modal leaks focus or that a redirect silently replaced the page under audit, both stay green while being broken. New page or new interactive primitive → extend the gate (see the app guide).
4. **Internal packages ship source, not build artifacts.** Private workspace packages (consumed only in-monorepo) point `exports` directly at `src/`; no `main`/`types` pointing to emitted output, no `build` script, no generated `dist/`. **Why**: file-watchers in dev (container sync, IDE, native watchers) almost always exclude generated directories to avoid host↔runtime collision: a build step at startup then makes every source change produce a stale artifact until manual rebuild. Source types are also more accurate than emitted `.d.ts`, and modern bundlers inline workspace deps from source at app build time. **Exception**: a package explicitly designed for npm publishing keeps its build pipeline, but its top-level `main`/`types`/`exports` still point at `src/`: the rewrite to `dist/` happens only at publish time via `publishConfig.{main,types,exports}`. **Why**: pointing top-level fields at `dist/` re-creates the stale-artifact trap for every monorepo consumer (a fresh clone has no `dist/` → `Cannot find module` until someone runs a build). The moment the answer to "is this published?" is no, the build (and the `publishConfig` block) goes.
5. **Typed query builder first; raw SQL only when it has no equivalent.** All data access goes through the typed builder and its helpers. A raw SQL fragment is acceptable only for what the builder does not model: DDL, session-scoped runtime tuning, or an operator with no helper (check the builder's exports first), and it keeps its column references typed so a rename still breaks the build. **Why**: the typed builder catches column rename and type drift at compile time; raw SQL silently rots until a runtime exception in prod. Concrete helpers: `packages/drizzle/CLAUDE.md`.
6. **Every state change emits a domain event; if it's worth doing, it's worth observing.** Any action that mutates persistent state (aggregate transition, lifecycle hook, service-level write, third-party library callback or webhook) declares a typed event in the shared catalog and emits it inside the same transaction as the write. **Why**: the downstream rail (audit trail, webhooks, future analytics and notifications) is opt-out, not opt-in: every silent mutation is a compliance gap (no audit trail), an integration gap (consumers can't subscribe) and a debugging gap (no event timeline). Adding the event costs a few lines, retrofitting one across N call sites costs hours. **Test before merging a state change**: trace the action to an emit call within the same transaction; if you cannot find one, you forgot. **Two recurring traps**: (a) declaring an event in the catalog with no emit site (an orphan, caught by querying the event store for the type and finding zero rows in the QA pass); (b) wiring only one of several lifecycles of a third-party library that produce the same state (e.g. both "member added" and "invitation accepted" produce a member; missing one drops every flow that uses it). **Exception, infra retention sweeps**: deleting aged rows from derived pipeline tables (event store, audit log, delivery logs, email queue) is not a state change, the business event was already emitted at write time and the sweep removes its own audit trace; the same holds for a coordination lease and for the bookkeeping of a delivery queue (attempts, lease, dead state), which describes how a row travels, not a change of business state: the one fact announced is the first death, once, in the unit of work that stores it. Outbox delivery bookkeeping (attempts, deliveries, dead state, lease) is not a state change either: it records how an already emitted event travels, and the death of an event is announced once by a dedicated event so operators learn of it without every retry flooding the audit trail. Declaration and emit mechanics: `packages/events/CLAUDE.md` and `apps/api/CLAUDE.md`.
7. **Every event payload identifies its actor; an audit row attributed to "system" must be the real exception, not a default.** The payload of a state-change event carries the user who triggered it under a recognized key (priority list in `packages/events/CLAUDE.md`): the canonical `actorUserId` is REQUIRED whenever the actor differs from the subject; a bare `userId` stands for the actor only when subject and actor are the same (sign-in, self-deletion, MFA toggle). **Why**: compliance hinges on "who did what to whom"; an audit row with no actor has zero forensic value. **Test before merging an event payload**: ask "is the subject the actor?"; if not, `actorUserId` is a separate, NOT NULL field. Genuinely system-triggered (cron, cascade, webhook bridge with no upstream user) → nullable, and the nullability is explicit in the schema, not implicit. **Two recurring traps**: (a) reusing `userId` as actor when the row is a *target* (a kicked member's id is the subject, not the admin who kicked); (b) forgetting to propagate the actor from the HTTP boundary down to the service: it is threaded as an explicit argument, never inferred later from ambient session state.
8. **Every I/O method declares a span; every catch surfaces the error to telemetry.** Repositories and external-I/O services receive the instrumentation port by constructor injection, wrap their public methods in an outer span, wrap the actual query or network call in an inner span, and `catch` → capture → return a typed failure (or rethrow when the method throws by contract). **Why**: errors silently swallowed inside an infra catch are the #1 source of "we have no idea why it broke in prod"; the telemetry hook sits exactly here and swapping the provider never touches a call site. **Test before merging a new repository**: every public method either opens a span or documents why not (pure compute, no I/O). **Three recurring traps**: (a) a module-level singleton instead of constructor injection breaks testability and the "swap the binding to a no-op = remove the provider" contract; (b) one inner span per query in a multi-query method is noise, keep only the outer; (c) calling a sibling repository method from inside a span orphans the inner spans, inline the query. **Exception, pure-compute helpers** (signing, jitter, mappers) get neither span nor capture. **Front counterpart**: unexpected async failures reach telemetry through global handlers wired once at the query-client level, never through per-call-site capture in local error callbacks; expected failures (4xx, cancellations, flow-control signals) stay UX-only. **Why**: global handlers make every new query or mutation observable without opting in, and per-callback capture both double-reports and bypasses the expected-error filter. Mechanics: `apps/api/CLAUDE.md` and `apps/app/CLAUDE.md`.

## Turborepo

`ui: "tui"`; the daemon is auto-managed. `globalDependencies` (`biome.json`, `pnpm-workspace.yaml`, `.env*`) bust every cache; `inputs` are scoped per task so README and doc edits don't invalidate code caches. `type-check` stays an independent task, never a `with` sibling of `build`: the sibling is terminated when `build` exits, so a slow type-check dies without failing the run and the gate passes on broken types. `dev`, `test:watch` and `db:studio` are `interruptible`.

## Scripts & local infrastructure

`pnpm bootstrap` (copies `.env.example` → `.env` in `apps/api`, `apps/app` and `packages/drizzle`, idempotent) · `pnpm dev` (Turbo TUI, `--filter=<app>` to scope) · `dev:docker` (`docker compose up --watch`, fully containerized hot reload) · `build` · `test` · `type-check` · `check` (Biome) · `fix` · `ci:check` · `check:duplication` · `check:unused` · `ui:add` · `db:push` / `db:generate` / `db:migrate` / `db:seed` / `db:studio` · `clean`.

- Postgres runs on `localhost:5433` (never pin it back to 5432, it collides with a system Postgres): `docker compose up postgres -d` for native dev. `docker compose up -d` without arguments starts postgres + api + app and collides with `pnpm dev` on ports 3000 and 5173.
- Opt-in profiles: `--profile storage` (SeaweedFS, host port `8333`), `--profile sso` (Keycloak, host port `8080`, see `docs/SSO-LOCAL.md`).
- After a schema change: `pnpm db:push` (dev, non-interactive) or `db:generate && db:migrate` (prod-style). `db:push` applies the schema only and skips the data steps of migrations, so a local account that needs one (an existing admin who is not listed in `PLATFORM_ADMIN_IDS` gets no staff row) needs `db:migrate` or the env list.

## Release flow

Two-branch model. **`main` = released; `dev` = integration.** Every merge to `main` triggers semantic-release.

- **Conventional Commits required** (commitlint enforces a lower-case subject). Release impact (`.releaserc.json`): `feat` → minor; `fix`/`perf`/`refactor`/`revert`/`build` and `docs(readme)` → patch; `docs`/`style`/`test`/`chore`/`ci` → no release; `BREAKING CHANGE:` footer (or `!`) → major; a wrapped prose line starting with `BREAKING` does not cut a major. Pick the type for the *release impact you want*, not the file touched.
- Daily work on `dev` (or feature branches PR'd into `dev`). Pushing to `dev` does **not** release.
- Shipping = open a PR `dev` → `main` and merge it. semantic-release analyzes the commits since the last tag → one bundled bump + changelog.
- **`dev` → `main` MUST be a merge commit** (not squash, not rebase): squash collapses every conventional commit into one and semantic-release would see a single entry. GitHub allows merge commits only.
- `main` is protected (require PR, no force push, conversation resolution). A CI fix during release goes on `dev`, then re-merge.
- **Don't release on every commit**: wait for a meaningful batch. Don't push directly to `main`.
